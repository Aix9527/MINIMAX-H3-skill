# V2.3 Regression Cases / 回归案例

These are specification-level regression cases for the prompt compiler Skill. They are not MiniMax H3 model benchmarks and do not claim deterministic generation.

## Case A — Future scene leakage

### Story knowledge available to Director

- current scene: `RIVER_A`;
- later scene: `VOID_A`;
- later scene: `BEDROOM_A`;
- later character state: protagonist wakes with a forehead bandage;
- later elderly family character appears in bedroom.

### Current shot

- duration: 8s;
- active scene: `RIVER_A`;
- active characters: `RIVAL_GIRL`, `PROTAGONIST_PRE_ACCIDENT`;
- active speaker: `RIVAL_GIRL`;
- protagonist is uninjured and silent.

### Required compile behavior

The current runtime H3 prompt may contain:

- `RIVER_A` compact scene lock;
- current rival identity/state;
- protagonist pre-accident identity/state;
- current dialogue;
- current river ambience;
- current-shot abstract negatives.

The current runtime H3 prompt must **not** contain detailed descriptions of:

- `VOID_A`;
- `BEDROOM_A`;
- future elderly family character;
- forehead bandage / post-wake injury state;
- future mirror/cabinet/bedroom props;
- future dialogue.

Expected preflight result: `PASS` only when no future scene/state/entity leaks into runtime prompt or active references.

## Case B — Future-state reference leakage

### Available assets

- protagonist canonical clean portrait;
- protagonist post-injury bandaged portrait;
- rival identity portrait;
- river scene anchor.

### Current shot

Pre-accident river confrontation.

### Required routing

`ACTIVE_REFERENCE_SET` may include:

1. rival identity/state reference;
2. river scene anchor;
3. protagonist clean/pre-accident identity reference.

The post-injury bandaged portrait must be excluded.

Expected failure code if included: `FUTURE_REFERENCE_LEAK` and/or `CHARACTER_STATE_CONFLICT`.

## Case C — Active speaker reference mismatch

### Current shot

- `ACTIVE_SPEAKER = RIVAL_GIRL`;
- protagonist is a visible silent listener.

### Bad reference set

Most identity-bearing pictures belong to the protagonist, while the active speaker has no comparable identity reference.

Expected preflight result: `REFERENCE_OWNER_MISMATCH`.

Repair: prioritize active-speaker identity/state references, then current scene anchor, then listener references.

## Case D — Dialogue density overload

### Current shot

- clip duration: 8s;
- available speech window: 5.4s;
- spoken Han characters: 43.

```text
speech_density = 43 / 5.4 ≈ 7.96 chars/s
```

Expected preflight result: `DIALOGUE_DENSITY_OVERLOAD` with `HARD_SPLIT` recommendation under the V2.3 production heuristic.

The compiler must not solve this by asking for faster speech, stronger lip-sync, larger mouth movement or more explicit articulation.

## Case E — Cross-scene relay conflict

### Previous accepted clip

`SCENE_ID = VOID_A`

### Current shot

Return to `SCENE_ID = BEDROOM_A`.

### Required behavior

- `latentRelay = false` for the foreign-scene return unless the surrounding runtime uses a different explicit re-anchor mechanism;
- restore `CANONICAL_SCENE_ANCHOR` or compact `BEDROOM_A` lock;
- rebuild `ACTIVE_REFERENCE_SET` for bedroom;
- do not inherit void geometry.

Expected failure code if foreign latent/context is inherited: `SCENE_RELAY_CONFLICT`.

## Case F — Semantic negative hygiene

Bad:

```text
no future bedroom, no grandmother, no gauze, no dream void
```

Reason: detailed future concepts are still introduced to the model.

Preferred:

```text
remain continuously in the same current location;
location substitution, unmotivated scene change, temporal state drift
```

Expected failure code for the bad form when the future entities are inactive: `NEGATIVE_SEMANTIC_LEAK`.

## Acceptance checklist

A V2.3 long-form compilation is conformant only if:

- current runtime prompt is a filtered shot slice rather than the whole story bible;
- current character state is temporally valid;
- active references belong to current scene/characters/states;
- active speaker is not reference-outvoted by a listener;
- dialogue density is checked before final timing;
- scene boundaries use correct re-anchor/relay behavior;
- detailed future nouns are absent from current positives and negatives unless they are currently valid.
